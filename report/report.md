# ОТЧЕТ

---

1. у метода класса левый аргумент это `*this` поэтому `2u + Fraction()` будет выьерать перегрузку из `(uint_32_t).operator+(Fraction)` (но такой перегрузки нет и быть не может) и `operator+(uint32_t, Fraction)` (выберается эта перегрузка, а она обязана быть свободной). `friend` нужен чтобы иметь доступ ко всем полям `Fraction`. если оператор был бы методом оно бы не компилировалось, а если бы функцией без дружбы то не имело бы доступа к приватным полям
2. мутабельные операции изменяют сам объект и потому возвращают ссылку на измененный ответ, в отличие от иммутабельных, которые просто создают новый объект. если мы возвращаем из функции объект по значению он `prvalue` (например `(a += b) *= c` будет работать не так потому что `(a += b)` это `prvalue` и умножение на `c` происходит для него а не для `a` как то подразумевается) и изменяется объект который тут же удаляется, поэтому мы возвращаем `lvalue`. иммутабельные операторы возвращают наоборот по значению а не по ссылке потому что новый объект сразу же разрушится (при возвращении по ссылке) и в результате выйдет ссылка на несуществующий больше объект (по значению объект остается живым)
3. при выборе есть 3 варианта перегрузки `operator*(Frac&, Frac&)`, `operator*(Frac&, uint)`, `operator*(uint, Frac&)`. для первой нужно вызвать констуктор от `signed int`, для второй нужно вызвать статик каст к `uint`, 3 не подходит по сигнатуре. статик каст по стандартным типам имеет более высокий приоритет выбора чем вызов конструктора от объекта по правилу стандартное перобразование лучше пользовательского. итого мы получим `Frac(1,2) * UINT32_MAX` потому что `-1` кастится в максимальное значение (преобразование по модулю $2^32$) `unsigned` типа  `4294967295/2`
4. он вызывает виртуальную функцию `print()` из `vtable` переданного `const Expression &e` потому что `Expression` полиморфный класс.
5. чтобы правильно вызывалась диаллокация рессурсов по стандарту иначе возникает UB, так называемое. если диструктора не окажется в `vtable` то будет вызываться стандартный деструктор `Expression` (потому что наш указатель имеет такой тип, особенно важно для указателя, потому что для него вызов `delete` происходит от `~Expression()` если нет указателя в `vtable`) и например для `BinaryExpression` не будет освобождть дополнительно занятые ресурсы под указатели на выражения (кстати их деструкторы тоже вызывались бы от `Expression` если бы вызывались, что на практике не происходит)
